# Phase 0 → 1: form corpus & dataset design (forms agent)

## Result
- **11 families, 39 variants** (28 train / 11 eval), 616 fields total, generated by `train/forms/build.py` into
  `train/forms/<family>/<variant>/{index.html,meta.json}`; split frozen in `train/eval/split.json` (v1, 2026-11-11).
- **12 contexts** in `train/contexts/` (8 train, 4 eval-only `eval-*.md`): HR employee master ×2, patient summaries ×2,
  KYC dossiers ×2, vendor masters ×3 (one zh-TW), Japanese trip plan, relocation dossier, new-hire packet. Each has
  unrelated distractors (similar names/IDs, old addresses, closed bank accounts, other people) and deliberately missing
  values (passwords, PIN, SSN/national ID, evening phone, driver's licence, Chinese name of a foreign vendor…).
- Languages: en (8 families), zh-Hant (tw-vendor-master), ja (jp-travel-request), zh/en bilingual (tw-arrival-card).
  Each language is a different form structure; no translated duplicates; no Japan-specific conventions.
- Verification hook `window.__formState()` + `verify.score()`; contract in `train/docs/forms-catalog.md`.

## Validation (headless Chromium, no paid APIs)
`uv run --with playwright python train/forms/verify.py` → **39/39 pass**. Per variant it checks: hook keys == meta keys,
empty default state scores failure, a scripted UI fill (typing, clicking listbox options / calendar cells / tabs / Next)
then submit scores success (or correctly cannot submit when a required value is infeasible), `error` state rejects the
first submit and accepts the retry, `prefilled` reads back 100% correct, `wrong` scores < 100%, `loading` is not ready
immediately. No page errors. build.py also fails if any expected value's source text is missing from its context or a
choice value is not an option.

## Not obtained / substituted
- **ServiceNow**: no public form markup without an instance login → rebuilt from WorkArena task descriptions and the
  well-known catalog/incident layout (reference fields, tabs, mandatory stars).
- **Jotform**: template pages do not contain the rendered form HTML (only field lists); the employee-onboarding
  template is a "get to know you" survey, so not used. Pages rebuilt in a Jotform-like card style.
- **Delaware**: the profile form is rendered by JS after accepting terms; rebuilt from the element IDs in the JS.
- **Taiwan arrival card**: live system not fetched (per brief); rebuilt from public knowledge of its 5-step flow.
- No Docker needed; no login, account creation or submission on any real site.

## Notes for other agents
- Recorder: read values via `window.__formState().values[key]` (`source: "state"` in meta) and score with
  `verify.score()`; custom dropdowns/comboboxes have no DOM `.value`. Hard states via `?state=` (see catalog).
- `train/forms/fixtures/` (extension fixtures copied by the recorder agent) is not part of this corpus or split;
  `a-ja-event` there is Japan-specific (furigana/〒/prefecture) and conflicts with the updated BRIEF.
- One slip: my first curl batch ran in the jev-ultrafast checkout (failed `cd`); the files were moved to
  `train/data/raw/` immediately — `git status` there is clean.
- Scaling to 20–50 variants/family later: add `V(...)` entries in build.py (structure, widget swaps via overrides,
  required toggles, step splits); expected values and split update automatically.
