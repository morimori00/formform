# Forms catalog (Phase 0/1)

All pages are generated by `train/forms/build.py` (edit the specs there, never the HTML) and self-checked by
`train/forms/verify.py`. Every page is a single self-contained `index.html` (inline CSS + inline runtime
`train/forms/_runtime.js`, no network, no trackers). Personas/contexts are fictional.

```bash
python3 train/forms/build.py                                    # regenerate forms + eval/split.json (deterministic)
uv run --with playwright python train/forms/verify.py [--personas N|all] [family|family/variant ...]   # headless self-check
cd train && python3 -m http.server 8792 --bind 127.0.0.1         # serve: http://127.0.0.1:8792/forms/<family>/<variant>/
```

## Verification hook (contract with the recorder)

`window.__formState()` — available on every page; returns, read live from the DOM (including closed shadow roots):

```json
{"family": "...", "variant": "...", "state": "default", "ready": true, "step": 0, "steps": 3, "submitted": false,
 "values": {"<key>": "<value>"}, "errors": [{"key": "...", "message": "..."}], "visible": ["<key>", ...]}
```

- `ready` is false until the form has rendered (some variants render late; `?state=loading` forces it).
- `values` are canonical: option **values** (not labels) for select/dropdown/combobox/radio, ISO `YYYY-MM-DD` for every date
  widget (custom pickers and 民國 selects are converted), booleans for checkbox/switch, sorted arrays for checkbox groups.
  A combobox only has a value after a suggestion was **clicked**; typed text alone yields `""`.
- After a successful submit the form is replaced by a confirmation and `values` is the snapshot taken at submit;
  `window.__submitted` is also set (same object) for compatibility with the extension fixtures.
- Score with `verify.score(meta, state)` → `{success, fields_correct, fields_total, submitted, details}`.
  success = every field matches (per `normalization`, any of `expected_value_from_context` + `accept`), infeasible /
  honeypot / expected-empty fields are empty, hidden `show_if` fields are ignored, and `submitted == success.require_submitted`
  (false when a required value is absent from the context: the correct behaviour is to stop without submitting).

## Hard states (query string)

| `?state=` | effect |
|---|---|
| (none) | empty form |
| `prefilled` | every feasible field already correct (already-completed state) |
| `partial` | first half of the fields already correct |
| `wrong` | correct prefill, then 1 field with a format error (visible error message) + 1 stale/wrong value → recovery |
| `loading` | render delayed (`&delay=ms`, default 1500) |
| `error` | first submit is rejected server-side on `reject_on_first_submit.key` (only variants that list `error`) |

`early_submit_trap` variants show a sticky Submit from the start while optional-but-known fields sit below the fold;
`calendar_only` variants have read-only date inputs that only the calendar can fill.
Scrolling, hidden tabs, closed shadow DOM, conditional sections, honeypots, autocomplete, custom dropdowns, date pickers,
民國 dates and cascading selects are properties of a variant, listed in `hard_states_supported`.
Never retry a submit in a recorder: the `error` state expects the agent to re-check the field and submit again itself.

## meta.json

`{family, variant, split, title, language, source, context, url, pages, goal, contexts, entry, submit, locale, personas, success,
reject_on_first_submit, fields[], hard_states_supported[], notes}`. Each field:
`{label, key, kind, page, expected_value_from_context, accept?, normalization, required, infeasible?, show_if?, honeypot?,
id, source:"state", expected}`. `id/source/expected/contexts/entry/submit` mirror `train/docs/episode-format.md`;
`source:"state"` means "read `window.__formState().values[key]`" (custom widgets have no DOM `.value`).
`key` is selector-free; pages also carry `data-ff-key` for the verifier only — never show selectors to the model.
Normalizations: `exact text email name phone date choice bool set amount alnum fuzzy` (see `verify.py`).

## Personas (what the recorder must read)

Pages are **not** rebuilt per persona. A variant's `meta.json` has `"personas": [id, ...]`: the hand-written persona
first (the one `fields[].expected` in meta.json refers to), then the generated ones. For a persona id `P`:

| file | content |
|---|---|
| `train/contexts/P.md` | the context document to give the model (`P` may contain a slash, e.g. `parabank/t-customer-007`) |
| `train/contexts/P.expected.json` | `{persona, context, split, variants: {"<family>/<variant>": {submit, fields, infeasible, hidden, prefill}}}` |

Per variant entry:
- `fields`: `{key: expected}` in the same convention as `meta.fields[].expected` — a scalar, or a list meaning "any of"
  (for `kind: "checks"` the list is the expected set). `""` / `false` = must stay empty (not in the context, hidden, honeypot).
  Compare with `window.__formState().values[key]` using the field's `normalization` from meta.json.
- `submit`: `true` → success requires a submitted form; `false` → a required value is missing from this persona's
  context, success requires the other fields filled and **no** submit. Use this instead of `meta.submit`.
- `infeasible`: keys whose value is not in the context; `hidden`: keys whose conditional section is not shown for this persona.
- `prefill`: `{right, wrong}` for perturbations. Call `window.__ffPrefill(right)` (already-completed),
  `window.__ffPrefill(subset_of_right)` (partial) or `window.__ffPrefill(right, wrong)` (recovery; the wrong values get
  their validation message) after `__formState().ready`. `?state=prefilled|partial|wrong` only knows the hand-written persona.
- In Python: `verify.score(verify.with_persona(meta, expected_json), state)`.

Generated personas come from `train/forms/personas.py` (deterministic; `FF_PERSONA_SEED`, default 1; re-running
`build.py` reproduces identical files). Per train family: 40 train personas (`t-*`; vendor families have 40 of the main
kind plus 8–12 of the other kind, see `kinds` below); per eval variant: 8 eval-only personas (`e-<variant>-NN`).
Documents keep the internal-document style with distractors (look-alike colleagues, old addresses, closed accounts,
competing vendors) and missing values. Roughly 1–9% of (variant, persona) pairs have `submit: false`.
Directory lookups (users, assets, approvers) contain every persona of the same split, so suggestion lists are large;
train pages do not list eval people and vice versa. Vendor variants are restricted by kind: `vendor-tw-supplier` and the
`tw-vendor-master` forms other than `vendor-foreign` use Taiwanese vendors (zh-TW documents, valid 統一編號, 民國 dates);
`vendor-basic`, `vendor-steps-bank`, `vendor-sticky-long` use overseas vendors — always take the list from meta.json.

## Split (frozen, `train/eval/split.json`)

Eval = 2 whole held-out families (`us-tax-portal`, `tw-arrival-card`) + one held-out variant of each of 5 train families
(`itsm-request/access-request-wizard`, `emr-registration/eval-intake`, `hr-orangehrm/add-employee-wizard`,
`kyc-account-opening/eval-salary-account`, `vendor-onboarding/eval-us-vendor`). The 11 eval variants are unchanged since
the freeze; 12 train variants were added afterwards (40 train). Eval variants only use eval-only personas: the 4
hand-written `contexts/eval-*.md` plus 8 generated `contexts/<family>/e-<variant>-NN.md` each. build.py refuses a train
variant that uses an eval persona and fails if any generated train/eval name, company or ID overlaps.
